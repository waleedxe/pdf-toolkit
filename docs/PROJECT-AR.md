# صندوق أدوات PDF — دليل المشروع (بالعربية)

> تطبيق سطح مكتب محلي بالكامل لنظام ويندوز، يعالج ملفات PDF على جهازك دون أي رفع أو إنترنت،
> بواجهة عربية وإنجليزية ودعم حقيقي للكتابة من اليمين إلى اليسار.

- **المستودع (خاص حاليًا):** https://github.com/waleedxe/pdf-toolkit
- **الإصدار الأول:** `v0.1.0` — https://github.com/waleedxe/pdf-toolkit/releases/tag/v0.1.0

---

## 1) ما هو المشروع؟

تطبيق سطح مكتب يقدّم أدوات PDF المعتادة (مثل مواقع الأدوات الشهيرة) لكن **يعمل محليًا**:

- لا رفع للملفات، ولا تحويل سحابي، ولا حسابات، ولا تتبّع.
- **العربية أولًا**: واجهة عربية/إنجليزية، تخطيط RTL، ودعم كتابة عربية حقيقي في المحتوى
  المُنشأ (تشكيل الحروف، ترتيب RTL، تضمين خط عربي داخل الملف الناتج).
- **لا يتم استبدال ملفك الأصلي أبدًا**: كل عملية تُنتج ملفًا جديدًا، ومع أسماء آمنة عند التعارض.
- **واجهة سريعة**: العمل الثقيل يجري في الخلفية (Rust)، والمصغّرات تُرسم عند الحاجة فقط.

### الأدوات الاثنا عشر (كلها تعمل)

| الفئة | الأدوات |
| --- | --- |
| تنظيم | دمج PDF · تقسيم PDF · استخراج صفحات · حذف صفحات · إعادة ترتيب الصفحات |
| تحويل | صور إلى PDF (JPG/PNG/WebP) · PDF إلى صور (PNG/JPG) |
| تحرير | تدوير الصفحات · علامة مائية (نص/صورة) · أرقام الصفحات |
| حماية | حماية بكلمة مرور (AES-128) · إزالة الحماية بكلمة المرور |

> إزالة الحماية تعمل فقط عند إدخال كلمة المرور الصحيحة — لا تخمين ولا تجاوز.

## 2) التقنيات (Tech Stack)

| الطبقة | التقنية | لماذا |
| --- | --- | --- |
| إطار سطح المكتب | **Tauri 2** | تطبيق صغير الحجم وسريع، يعتمد على WebView2 الموجود في ويندوز (وليس Electron) |
| الواجهة | **React 19 + TypeScript** | مكوّنات حديثة مع تحقق أنواع صارم |
| البناء | **Vite 8** | بناء سريع للواجهة |
| التنسيق | **Tailwind CSS v4** | تنسيق خفيف ومرن |
| إدارة الحالة | **Zustand** | حالة بسيطة (اللغة، التنقّل) |
| الترجمة | **i18next / react-i18next** | عربي + إنجليزي مع تبديل RTL/LTR |
| الخلفية | **Rust** | تنفيذ كل عمليات PDF بعيدًا عن واجهة المستخدم |
| معالجة PDF | **lopdf** (MIT) | دمج/تقسيم/استخراج/حذف/تدوير + التشفير |
| عرض الصفحات | **hayro** (Apache-2.0/MIT) | عرض الصور والمصغّرات — مكتبة Rust خالصة بلا مكتبات خارجية |
| تشكيل النص العربي | **rustybuzz + ttf-parser** | تشكيل الحروف العربية وترتيبها RTL |
| الصور | **image** (JPG/PNG/WebP) | قراءة/تحويل الصور |
| الخط العربي | **Amiri** (رخصة OFL 1.1) | يُضمَّن داخل ملف PDF الناتج لضمان ظهور العربية صحيحة |

جميع المكتبات برخص متسامحة (MIT/Apache/OFL) — لا GPL/AGPL. التفاصيل في
`THIRD_PARTY_LICENSES.md`.

## 3) معمارية التطبيق (Architecture)

الفكرة الأساسية: **فصل واضح بين الواجهة والمحرّكات**، بحيث يمكن تغيير محرّك PDF لاحقًا دون
لمس الواجهة.

```
الواجهة (React + TypeScript)
        │  استدعاء أمر Tauri (invoke)
        ▼
src-tauri/            ← طبقة رقيقة: أوامر + ذاكرة مؤقتة للمصغّرات
        ▼
crates/pdf-service    ← خدمات التطبيق: تسمية المخرجات + تنسيق العمليات
        ▼
crates/pdf-core       ← المعالجة + النصوص (lopdf, rustybuzz, image) والتشفير
crates/pdf-render     ← العرض والتصيير (hayro)
crates/pdf-core/text  ← تشكيل النص العربي + تضمين الخط
```

### مجلدات المشروع

```text
src/                      واجهة React
  app/ components/ features/ tools/ i18n/ stores/ hooks/ types/ lib/
crates/pdf-core/          منطق PDF (المعالجة، النص، الأمان)
crates/pdf-render/        العرض/التصيير (مصغّرات + PDF إلى صور)
crates/pdf-service/       خدمات التطبيق (تسمية + تنسيق) — قابلة للاختبار
src-tauri/                تطبيق Tauri (أوامر Rust)
assets/fonts/             خط Amiri + رخصته
.github/workflows/        CI + الإصدار
```

### مبدأ المحرّك (Adapter)
أي محرّك خارجي (lopdf/hayro/…) يُستخدم خلف واجهة داخلية ثابتة فقط. لا توجد استدعاءات مباشرة
منتشرة في المشروع.

## 4) كيف نُنتج ملف `.exe` (وماذا فعلنا بالضبط)

هناك ثلاثة مسارات:

### المسار أ — البناء محليًا على ويندوز (للتجريب السريع)
المتطلبات (مرة واحدة):
1. **Rust** (MSVC): من https://win.rustup.rs
2. **Visual Studio Build Tools** مع حزمة **Desktop development with C++**
3. **Node.js 20+**

ثم في PowerShell داخل المشروع:
```powershell
cd C:\Users\walee\Desktop\PDFtool\PDFtool
npm install
npm run tauri build
```
النواتج:
- **المثبِّت (Next → Next → Install):**
  `target\release\bundle\nsis\PDF Toolkit_0.1.0_x64-setup.exe`
- **النسخة المحمولة (بلا تثبيت):**
  `target\release\pdf-toolkit.exe`

> ملاحظة: لأن المشروع **Cargo workspace**، مجلد الإخراج هو `target` في **جذر المشروع**،
> وليس داخل `src-tauri\target`.

لتشغيل نسخة تطوير سريعة دون بناء: `npm run tauri dev`.

### المسار ب — البناء عبر GitHub (هذا ما استخدمناه — الأسهل)
1. ارفع الكود إلى فرع `main` (تم).
2. أنشئ وسم إصدار وارفعه:
   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```
3. يعمل سير عمل **Release** على جهاز ويندوز في GitHub ويبني:
   - المثبِّت `PDF.Toolkit_0.1.0_x64-setup.exe`
   - الحزمة المحمولة `PDF-Toolkit-portable-windows-x64.zip`
   ويرفعها إلى صفحة **Releases**.

هذا ما أنتج الإصدار `v0.1.0` الموجود لديك على سطح المكتب.

### المسار ج — CI للتحقق فقط
عند أي `push` إلى `main` يعمل سير عمل **CI** (فحص الواجهة + اختبارات Rust + فحص بناء التطبيق
على ويندوز).

> **ملاحظة مهمة:** البناء يجب أن يكون بـ **MSVC على ويندوز**. لقد جرّبنا البناء المتقاطع من
> لينكس (GNU) فنجح في إنتاج ملف، لكنه كان تالفًا وقت التشغيل — لذلك المسار المعتمد هو ويندوز/CI.

## 5) إذا كانت لدي ميزة جديدة… ما العملية؟

اتبع نفس النمط الموجود (لا تكسر البنية). الخطوات:

1. **المنطق في `crates/pdf-core`**
   - أنشئ ملف الأداة في `crates/pdf-core/src/tools/` مثلاً `my_tool.rs`.
   - صدّره من `tools/mod.rs` و`lib.rs`.
   - أضف اختبارات تكامل في `crates/pdf-core/tests/`.

2. **خدمة التطبيق في `crates/pdf-service`**
   - أضف دالة تستقبل مسارات و`Options` وتستدعي `pdf-core` (مع تسمية المخرجات الآمنة عند الحاجة).

3. **أمر Tauri في `src-tauri/src/commands/mod.rs`**
   - عرّف `struct Request` (serde) + دالة `#[tauri::command]`.
   - سجّلها في `src-tauri/src/lib.rs` داخل `generate_handler!`.

4. **الواجهة في `src/tools/<الاسم>/`**
   - مكوّن React يستخدم `invokeCommand` والأدوات المشتركة (`FileDropZone`, `useToolJob`,
     `ResultPanel`…).
   - سجّله في `src/tools/ToolView.tsx`.
   - أضف النصوص في `src/i18n/en.json` و`src/i18n/ar.json` (يجب أن تتطابق المفاتيح).

5. **التحقق (مهم — لا تُجمّع مراحل مكسورة)**
   ```bash
   cargo fmt --all
   cargo clippy -p pdf-core -p pdf-render -p pdf-service --all-targets -- -D warnings
   cargo test  -p pdf-core -p pdf-render -p pdf-service --all-targets

   npm run format:check && npm run lint && npm run typecheck && npm run test && npm run build
   ```

6. **النشر**
   - `git commit` ثم `git push` (يعمل CI تلقائيًا).
   - إصدار جديد: `git tag v0.1.1 && git push origin v0.1.1` → سير عمل Release ينتج المثبِّت.

### قواعد ثابتة
- لا تستبدل ملف المستخدم الأصلي؛ أنتج ملفًا جديدًا.
- لا تُنفّذ عملًا ثقيلًا في واجهة React؛ استخدم الخلفية (Rust).
- أي محرّك جديد يبقى خلف واجهة (adapter).
- حافظ على العربية أولًا: اختبر RTL والنص العربي عند أي تغيير يمسّ المحتوى.

## 7) ملاحظات مهمة

- **الخصوصية:** لا رفع، لا سحابة، لا تتبّع، لا محتوى ملفات في أي قياسات. انظر `PRIVACY.md`.
- **WebView2:** مطلوب، وهو مثبّت افتراضيًا في ويندوز 10/11.
- **التوقيع الرقمي:** التطبيق غير موقّع حاليًا، لذا قد يظهر تحذير SmartScreen مرة واحدة:
  More info → Run anyway. يمكن إضافة التوقيع لاحقًا عبر `bundle.windows.sign_command`.
- **الرخصة:** المشروع سيُفتح لاحقًا كمصدر مفتوح. المكتبات المستخدمة كلها برخص متسامحة.
